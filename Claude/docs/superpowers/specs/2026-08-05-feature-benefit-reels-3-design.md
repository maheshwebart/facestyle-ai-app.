# Feature Benefit Reels — Batch 3 (Design)

**Date:** 2026-08-05
**Branch:** `feature-benefit-reels`

## Goal

Six more B2C vertical reels for facestyle.fun (1080×1920, 30fps, 20–30s each), plus a
Pinterest pin and a caption file per reel, scheduled into Buffer across Instagram Reels,
YouTube Shorts, and Pinterest.

This is the third batch built on the existing `FeatureBenefitReel` component. Batches 1
and 2 shipped 12 reels between them; batch 3 adds no new composition code, only data.

## Why these six topics

The 12 existing reels already cover: instant render, privacy, hairstyle try-on, dress
try-on, hair + sunglasses, play with your look, face-shape matching, beard styling,
makeup try-on, any device, decision fatigue, and walk-in-knowing.

Batch 3 targets the *hesitation moments* — the specific decisions people stall on, where
a preview is the thing that unblocks them. Each reel answers one question the viewer has
already asked themselves.

## Architecture

No new components. `FeatureBenefitReel` (schema-driven: headline, subline, two photos with
captions, voiceover, music, durations, colors, end-card props) renders all six. `PinterestPin`
renders the six stills. Both already exist and are unmodified by this batch.

```
Reel structure (unchanged from batches 1–2):
  [0 .. body)          body Sequence  — headline beat → photo 1 beat → photo 2 beat (thirds)
                                        voiceover audio, music ducked to 0.18
  [body .. body+90)    EndCard        — music ramps to 0.35
```

### Duration math

Same convention as batches 1–2:

```
bodyDurationInFrames  = ceil(voiceSeconds * 30) + 45     // 1.5s settle pad
durationInFrames      = bodyDurationInFrames + 90        // EndCard hold
```

Batch 2 landed at 16–18s because its scripts were too short. Batch 3 scripts are written
to ~50–62 words, which at the measured Rachel delivery rate (~2.2 words/sec) puts each
reel at **24–28s** — inside the 20–30s target with margin at both ends.

Durations are computed from the *measured* MP3 lengths after generation, not estimated.
If any reel lands outside 20–30s, its script is trimmed or extended and the voiceover
regenerated, rather than padding to fake the length.

### Photos

Kling `kling-image-v3_0`, `aspect_ratio: "9:16"`, `img_resolution: "2k"`, 1 image per call.
**12 images, each charged.** The prompt list below is final — no exploratory generations,
no regenerating for taste without checking back in first.

Output: `public/images/feature-benefit-reels-3/benefit3-{1..6}-photo-{1,2}.png`

Every prompt keeps the batch-1/2 house style: photorealistic, young adult, plain
background, soft natural light, vertical portrait, `no text, no logos`. Within each pair,
photo 1 is the "before" state and photo 2 is the result.

**Face continuity (changed during implementation).** Generating both photos of a pair with
independent `text_to_image` calls produces two different people — the trait batches 1 and 2
already shipped with. Batch 3 leans harder on before/after, so photo 2 of reels 1–5 is
instead produced with `image_to_image`, feeding that reel's own photo 1 in as `image_1`.
Reel 6 keeps two distinct images by design (one person, then a group of friends).

Model notes from the actual run, worth reusing next time:

- `kling-image-o1` (1 credit) preserves identity well and handled colour, cut, bridal
  restyle and length changes — but only after prompts pinned the framing (`plain white
  t-shirt, shoulders up`) and, for colour, ruled out the failure mode explicitly (`not
  orange, not neon`). Its first pass produced neon-orange hair and chest-level crops.
- `kling-image-o1` twice refused to add a fringe, returning the reference face unchanged.
  `gemini-3-pro-image` did it correctly on the first try — but costs **20 credits**, not 1.
  Check a model's price before reaching for it.

## Deliverables per reel

1. **Video** — `out/promotional-3/{slug}.mp4`, 1080×1920, H.264 + AAC. One file serves both
   Instagram Reels and YouTube Shorts.
2. **Thumbnail** — `out/promotional-3/{slug}-thumb.jpg`, extracted from the photo-2 beat.
3. **Pinterest pin** — `out/promotional-3/pins/{slug}-pin.png`, 1000×1500, via
   `remotion still` on a new `Pin3*` composition reusing `PinterestPin` with the reel's
   photo-2 image. **Static image, not video** — Pinterest's spam filter blocked the
   video pins hosted on raw.githubusercontent.com during batch 2.
4. **Caption file** — `out/promotional-3/{slug}.txt` with Title / Description / Tags,
   matching the existing `out/promotional/*.txt` format.

Slugs: `hair-colour`, `big-chop`, `bangs`, `wedding-look`, `hair-length`, `friends-vote`.

## Rendering

Renders run on a rented **vast.ai** instance, not the local Windows machine, per the
established default for this project (local has crashed mid-render before). The known
setup gotchas — `libasound2t64`, `. /opt/nvm/nvm.sh &&` prefix for non-interactive SSH,
plain `scp` instead of `vastai copy`, destroying the instance from inside it — are
already solved and are not re-diagnosed here.

Verification after render, per file:
- `ffprobe` → `width=1080`, `height=1920`, duration within 20–30s and matching the
  computed total ±0.1s
- `ffprobe` audio stream → `codec_name=aac`

## Buffer scheduling

**There is no Buffer connector in this environment and no Buffer API code in the repo.**
Scheduling is browser-driven against the user's logged-in Buffer, one post at a time,
with the user confirming before each post is queued. This is a manual-assisted step, not
an automated one, and it is the last step — nothing is queued until all six reels pass
verification.

Cadence: 2 posts per week, Tuesday and Friday mornings IST, over three weeks.

| Slot | Reel | Channels |
|------|------|----------|
| Week 1 Tue | Hair Colour Try-On | Instagram Reels, YouTube Shorts, Pinterest |
| Week 1 Fri | Should You Get Bangs? | Instagram Reels, YouTube Shorts, Pinterest |
| Week 2 Tue | The Big Chop | Instagram Reels, YouTube Shorts, Pinterest |
| Week 2 Fri | Short, Medium, or Long? | Instagram Reels, YouTube Shorts, Pinterest |
| Week 3 Tue | Your Wedding Look, Trialled | Instagram Reels, YouTube Shorts, Pinterest |
| Week 3 Fri | Let Your Friends Vote | Instagram Reels, YouTube Shorts, Pinterest |

Ordering is not arbitrary: the two highest-intent, highest-search-volume topics (colour,
bangs) go first while the batch is freshest, and the share-driven reel closes the run so
its distribution benefits from three weeks of prior audience growth.

## Constraints

- B2C only. No salon, kiosk, or B2B messaging in any script, caption, or end card.
- Reuse `EASE_ENTER`/`EASE_EXIT` from `src/motion.ts` and `BRAND` from `src/config.ts`.
  No new easing curves, no new brand colors.
- Do not modify `FeatureBenefitReel.tsx`, `PinterestPin.tsx`, `EndCard.tsx`, or any
  batch-1 / batch-2 composition entry, asset, or render.
- `ELEVENLABS_API_KEY` lives only in `.env` (gitignored). Never hardcode, print, or commit it.
- Exactly 12 Kling images. Any additional generation is a charged decision that needs
  explicit sign-off first.
- New assets go under `public/audio/feature-benefit-reels-3/` and
  `public/images/feature-benefit-reels-3/`.

## Out of scope

- 4:5 or 1:1 variants (LinkedIn and Facebook feed were considered and dropped).
- Any change to the `FeatureBenefitReel` layout or motion design.
- Automated Buffer posting via API.
- Paid promotion of any of these six reels — that decision waits on the `attribution`
  work described in `facestyle-marketing-sequence.md`.
